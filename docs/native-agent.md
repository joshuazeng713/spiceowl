# Native agent Q&A

SpiceOwl 0.3.0a1 has a small real Q&A path beside its existing fake connection demo. It invokes an installed Codex runtime using that runtime's own configuration. A configured custom provider is not evidence of a ChatGPT subscription. SpiceOwl does not copy tokens, accept passwords, or log raw authentication/configuration responses.

Create a private JSON profile with your actual installed executable. All values here are fictional:

```json
{
  "schema": "spiceowl.agent.v1",
  "agent_id": "my-codex",
  "label": "My native Codex",
  "executable": "/opt/example/bin/codex",
  "model": null
}
```

`model: null` uses the runtime's configured default. A profile may specify an explicit available model; there is no automatic fallback to another model/provider. Profile import does not invoke the runtime. Keep the profile in an ignored `*.local.json` file or private directory.

```bash
spiceowl --data-dir /home/example/state/spiceowl agents add --file /home/example/private/agent.local.json
spiceowl --data-dir /home/example/state/spiceowl agents list
spiceowl --data-dir /home/example/state/spiceowl agents probe my-codex
spiceowl --data-dir /home/example/state/spiceowl serve
```

Open **Agent chat**, select the native connection, and send a short question. This starts a real inference request using the configured provider's account/quota. Runtime readiness probing does not prove inference access. Only a completed answer establishes that the particular request succeeded. The browser displays the returned model, provider, status and answer; it does not expose the executable or credentials.

The request is text-only and has bounded duration/output. This adapter is qualified against native version `0.167.0-alpha.4.1`; other versions fail the compatibility check until qualified. It discovers inherited MCP server names, disables them for its own process, and verifies the effective restrictions before starting an ephemeral native thread. Global user configuration remains unchanged. The question budget is 120 seconds after metadata preparation, and answer output is bounded.

The integration keeps filesystem permissions read-only and disables tool families. It does not attach to existing user chats or let the model operate simulations. Native provider/rate-limit failures remain visible; no replacement provider is silently charged. The adapter does not replay a question; the native runtime retains its internal provider transport/retry policy. The existing **AI connections** demo cards and per-run fixture diagnosis remain synthetic.

For standalone CLI use, stop the web controller first so only one controller owns inference records:

```bash
spiceowl --data-dir /home/example/state/spiceowl agents ask my-codex --question "Does a lost SSH connection prove a simulation failed?" --request-key first-question
spiceowl --data-dir /home/example/state/spiceowl questions list
spiceowl --data-dir /home/example/state/spiceowl questions inspect QA_ID
```

An identical request key and identical question return the stored request. The key cannot be reused for different input. On controller restart, unfinished questions become `outcome_unknown`; they are not resent. An unresolved question blocks another question on the same connection until its outcome is addressed. Cost is unknown unless the provider returns usable accounting; token counts are not a monetary charge.

Native Q&A and MCP serve opposite directions. Native Q&A sends the user's text to an agent runtime. SpiceOwl's optional MCP server lets an existing client read saved local observations and never initiates inference. MCP registration does not automatically connect the web question form to an existing chat.

The official app-server protocol, initialization and turn lifecycle are documented in [OpenAI's app-server documentation](https://learn.chatgpt.com/docs/app-server). Supported behavior is also checked against schemas generated by the installed Codex binary. This adapter is an early compatibility slice; it fails closed when required protocol/tool restrictions cannot be established.
